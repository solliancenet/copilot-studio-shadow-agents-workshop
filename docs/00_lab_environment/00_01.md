# Task 00-01 — Get your lab access

## Introduction

You cannot review what you cannot see. Before any of the analysis modules, you need two things: read-only
access to the shared Halcourt Mutual demo tenant, and the offline **artifact pack**, so the analysis work
continues even if live tenant access is slow or unavailable. This task gets you both and confirms they open.

## Description

You will sign in to the shared demo tenant with the lab account the facilitator hands out, open the
**Power Platform admin center** (PPAC) and confirm you can see — but not change — the environments list,
then download the artifact pack and open all five CSV exports. This is a HYBRID lab: the live tenant and
the exported pack each let you answer the same questions, so a slow tenant never blocks you.

## Success Criteria

- [ ] You can sign in to the shared Halcourt Mutual demo tenant using the lab account the facilitator handed out.
- [ ] The Power Platform admin center opens and you can see the **Environments** list in read-only mode.
- [ ] You have downloaded the artifact pack from the Estate Binder.
- [ ] All five CSVs open cleanly: `agents-export.csv`, `connections-export.csv`, `agent-identities-export.csv`, `users-export.csv`, `environments-export.csv`.

## Key Tasks

### 01: Get into the demo tenant and open the Power Platform admin center

<details markdown="block">
<summary>Expand this section for detailed steps</summary>

1. Get your **lab account** from the facilitator: a username and password for an account in the lab tenant, along with the tenant's domain and your **estate id** (for example `mgray`). The domain is the one Microsoft assigned the lab tenant — usually not the `halcourtmutual.onmicrosoft.com` you'll see in these pages and the artifact pack.

   One tenant can hold several copies of the Halcourt Mutual estate, so the names your copy creates carry the id. Where a lab page shows a plain name, look for:

   - **Accounts:** `marcus.webb.<id>@<domain>` and *Marcus Webb (&lt;id&gt;)* for `marcus.webb@halcourtmutual.onmicrosoft.com` and *Marcus Webb*.
   - **Environments, groups, SharePoint sites, the DLP policy:** `Claims-Test-<id>`, `All-Employees-<id>`, `HR-Benefits-<id>`, `Halcourt-Prod-DLP-<id>`.
   - **The two agents in the default environment:** *Expense Helper (&lt;id&gt;)* and *Onboarding Guide (&lt;id&gt;)*.

   Everything else keeps its plain name: the other eight agents (*Benefits Buddy* is still *Benefits Buddy*, in `Halcourt-Prod-<id>`), and the two things a tenant has only one of — the `Halcourt (default)` environment and its Conditional Access policies, which every estate shares. An agent's Entra identity is named after the agent and carries no id of its own. So if the tenant holds more than one estate, expect other estates' agents in the default environment, and identically named agent identities in Entra. The artifact pack keeps the plain names throughout.
2. Open a private browser window, so your own work account doesn't sign you in to the wrong tenant, and go to the **Power Platform admin center** at `https://admin.powerplatform.microsoft.com`. Sign in with your lab account.
3. In the left rail, choose **Manage**, then **Environments**. Confirm you can see the environments list.
4. Confirm your access is **read-only**: you can open and view environments and their details, but creation, edit, and delete controls are unavailable or blocked. That is expected — a security reviewer observes; they do not change the estate.

![Power Platform admin center showing the Halcourt Mutual environments list in read-only view](../../media/ex00_t01_kt01_s01.png)

</details>

### 02: Download the artifact pack and open the five CSVs

<details markdown="block">
<summary>Expand this section for detailed steps</summary>

1. Open the [Estate Binder]({% link worksheets/index.md %}) and find **The artifact pack** section.
2. Download all five exports: [`agents-export.csv`]({% link worksheets/artifact-pack/agents-export.csv %}), [`connections-export.csv`]({% link worksheets/artifact-pack/connections-export.csv %}), [`agent-identities-export.csv`]({% link worksheets/artifact-pack/agent-identities-export.csv %}), [`users-export.csv`]({% link worksheets/artifact-pack/users-export.csv %}), and [`environments-export.csv`]({% link worksheets/artifact-pack/environments-export.csv %}).
3. Open each CSV in a spreadsheet tool (or a text editor). Confirm the header row and a handful of data rows render — no need to analyze anything yet.
4. Sanity-check that the files are joinable: `agents-export.csv` names an `environment` and an `owner_upn`; `environments-export.csv` lists those same environments; `users-export.csv` lists those same UPNs. You will join across them in Module 2.

</details>

{: .note }
> This is a HYBRID lab. If tenant access is slow, degraded, or unavailable, the **artifact pack alone is
> enough** to complete every discovery and analysis module. The live tenant is a convenience, not a
> dependency — never sit blocked waiting on it.

## Summary

You now have both ways in: a read-only seat in the Halcourt Mutual tenant and the offline artifact pack.
You confirmed the Power Platform admin center opens and that all five exports are readable and joinable.
That is everything you need to start asking how many agents there are, who owns them, and what they can
reach. Next, get oriented to the org and the day.
