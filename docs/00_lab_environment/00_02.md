# Task 00-02 — Meet Meridian Mutual

## Introduction

Before you hunt for problems, learn the terrain. A security review that starts by naming the environments,
the identities, and the systems in play is far harder to fool than one that dives straight into a single
agent. This task orients you to Meridian Mutual, its four Power Platform environments, and where the day
is headed.

## Description

You will read the **four environments** straight from `environments-export.csv`, walk the day's arc from
**DISCOVER** to **OPERATIONALIZE**, and skim all five exports to feel how hard the three questions really
are. You are not producing findings here — you are building a mental map so the later modules land. You
will also locate the Estate Binder templates you fill in as you go.

## Success Criteria

- [ ] You can name Meridian Mutual's four environments and, for each, read its type, DLP policy, and managed status from `environments-export.csv`.
- [ ] You can state the day's arc: **DISCOVER → MAP → BREAK → CONTROL → RETEST → OPERATIONALIZE**, and which module each phase maps to.
- [ ] You have skimmed all five CSVs and can restate the three questions — how many agents, who owns them, what can they access — in your own words.
- [ ] You know where the Estate Binder templates live and that you build one deliverable per phase.

## Key Tasks

### 01: Read the four environments

<details markdown="block">
<summary>Expand this section for detailed steps</summary>

1. Open [`environments-export.csv`]({% link worksheets/artifact-pack/environments-export.csv %}) (or the **Environments** page in the Power Platform admin center — they describe the same four environments).
2. List all four environments and, for each, note its **type**, whether a **DLP policy** is applied, whether it is **managed**, and who has **maker access**:

   | Environment | Type | DLP policy | Managed | Maker access |
   |---|---|---|---|---|
   | Meridian (default) | Default | *(none)* | No | All users |
   | Meridian-Prod | Production | Meridian-Prod-DLP | Yes | Makers group |
   | Claims-Test | Sandbox | *(none)* | No | Claims team |
   | Maker-Sandbox | Developer | *(none)* | No | Individual maker |

3. Read the table without judging it yet. Just notice the shape: which environments carry a DLP policy and which do not; which are managed; who is allowed to build in each. You will come back to these facts in Module 2 and decide what they mean.
4. Note the trust-boundary question you will keep asking all day: **whose authority does an agent exercise, and what can it reach when it does?** Where an agent lives — and whether that environment has guardrails — is the first clue.

</details>

### 02: Walk the day arc and skim the pack

<details markdown="block">
<summary>Expand this section for detailed steps</summary>

1. Fix the through-line in your head. The whole day moves along one arc:

   ```mermaid
   flowchart LR
     D[DISCOVER] --> M[MAP] --> B[BREAK] --> C[CONTROL] --> R[RETEST] --> O[OPERATIONALIZE]
   ```

2. Map each phase to where you will do it:
   - **DISCOVER** — inventory every agent, everywhere ([Module 2]({% link docs/02_discover_and_inventory/02_discover_and_inventory.md %})).
   - **MAP** — trace identity, authorization, and effective access ([Module 3]({% link docs/03_identity_and_effective_access/03_identity_and_effective_access.md %})).
   - **BREAK** — observe the failure modes in controlled scenarios ([Module 4]({% link docs/04_break_the_agents/04_break_the_agents.md %})).
   - **CONTROL / RETEST** — put Microsoft's controls to the test and rule **CLOSES IT / DENTS IT / MISSES IT** ([Module 5]({% link docs/05_test_the_controls/05_test_the_controls.md %})).
   - **OPERATIONALIZE** — turn it into a repeatable baseline ([Module 6]({% link docs/06_security_baseline/06_security_baseline.md %})).
3. Skim each of the five CSVs for two minutes total. Do not analyze — just feel the weight of the three questions: how many agents are there, who owns each one, and what does each one connect to? Notice that no single file answers any question on its own; the answers live in the joins between them.
4. Open the [Estate Binder]({% link worksheets/index.md %}). You will produce one deliverable per phase — the first is the **Agent Estate Inventory** in Module 2. Keep the binder handy; you fill it in as you work.

</details>

{: .tip }
> No single export tells the whole story. An agent whose owner has left, a connection owned by someone who
> is gone, an agent in an environment with no DLP — those only appear when you **join** the files. That is
> the skill Module 2 builds; today just notice how the pieces fit together.

## Summary

You have met Meridian Mutual: a regulated insurer with four Power Platform environments, a fleet of
maker-built Copilot Studio agents, and no one who can answer the three questions. You read the
environments from the export, walked the day's arc from DISCOVER to OPERATIONALIZE, and found the Estate
Binder you will fill in along the way. With the terrain mapped, you are ready to start counting agents in
Module 2.
