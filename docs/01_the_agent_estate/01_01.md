# Task 01-01 — The three questions

## Introduction

Every agent-governance conversation collapses into three questions: **How many agents do we have? Who
owns them? What can they access?** They sound like a five-minute lookup. They are not — and feeling *why*
they are hard, before you have any tooling, is the point of this task. Since March 2026 every new Copilot
Studio agent gets its own Entra identity automatically, and Agent 365 (GA May 2026) put an admin surface
on top; but a governance surface is not the same as an answer. You still have to assemble the answer from
data that is scattered across environments, connections, and identities.

## Description

You will take the three questions to the exported [artifact pack]({% link worksheets/index.md %}#the-artifact-pack)
and try to answer each one for the Halcourt Mutual estate — as a quick gut-check, not a full inventory
(that is Module 2). Along the way you will notice that no single export answers any question cleanly: the
findings live in the *joins* between files. Record how far you get and where you get stuck.

## Success Criteria

- [ ] You have opened all five artifact-pack CSVs and can say which columns each one carries.
- [ ] You have a first count of agents from `agents-export.csv`, and you can name at least one reason that
      count might be incomplete for a real tenant.
- [ ] For the "who owns them" question, you have flagged at least two rows where *owner* is not a clean,
      accountable answer (for example a disabled account, a service account, or a shared mailbox).
- [ ] You have attempted "what can they access" for a single agent and listed which files you had to join
      to get even a partial answer.
- [ ] You can state, in one sentence, why these three questions are hard to answer at a glance.

## Key Tasks

### 01: How many agents do we have?

Get a first count from the exports, then stress-test whether that count is really complete.

<details markdown="block">
<summary>Expand this section for detailed steps</summary>

1. Open [`agents-export.csv`]({% link worksheets/artifact-pack/agents-export.csv %}) and count the rows.
   That is your starting number of agents.
2. Look at the `environment` column. Note how many *distinct* environments the agents live in, then
   compare against [`environments-export.csv`]({% link worksheets/artifact-pack/environments-export.csv %}).
   Is every environment represented? Which environment types (Default, Production, Sandbox, Developer)
   are in scope?
3. Ask the harder question: in a real tenant, would this export contain *every* agent? Consider agents
   built in a personal Developer or Default environment that IT never registered. Write down why a
   maker-owned environment is a blind spot for any centrally-produced count.
4. Record your count and a one-line caveat about what it might be missing.

</details>

![Screenshot of agents-export.csv open in a spreadsheet, one row per agent](../../media/ex01_t01_kt01_s01.png)

### 02: Who owns them?

An owner column looks like an answer. Cross-check it against the account data and watch it get slippery.

<details markdown="block">
<summary>Expand this section for detailed steps</summary>

1. In `agents-export.csv`, read the `owner_upn` column for each agent. On its face, every agent has an
   owner.
2. Now join each `owner_upn` to [`users-export.csv`]({% link worksheets/artifact-pack/users-export.csv %})
   and look at three columns: `account_enabled`, `is_service_account`, and `is_shared_mailbox`.
3. Flag any owner that is not a real, present, accountable person — a **disabled** account, a **service
   account**, or a **shared mailbox**. For each, ask: if this agent misbehaved tomorrow, who would you
   call?
4. Open [`connections-export.csv`]({% link worksheets/artifact-pack/connections-export.csv %}) and compare
   `connection_owner_upn` against the agent's `owner_upn`. Note any agent where the person who owns the
   *connection* (and therefore the real credentials) is not the person who owns the *agent*.
5. Hold these observations. You will not resolve them here — Module 2 turns them into named findings — but
   noticing that "owner" has several different meanings is the whole point.

</details>

### 03: What can they access?

This is the question the day is really about. Try to answer it for one agent and watch how many files you
have to touch.

<details markdown="block">
<summary>Expand this section for detailed steps</summary>

1. Pick a single agent from `agents-export.csv`.
2. Try to write one paragraph describing everything it can reach. To do it, you will need to join across
   files: `connections-export.csv` (which connector and auth type), `agent-identities-export.csv` (the
   agent's Entra identity), and `environments-export.csv` (whether the environment has any DLP).
3. Notice what is *still* missing even after the joins — for example, the specific SharePoint site or
   Dataverse tables the connection can read, or the exact API the HTTP action calls. That detail lives in
   the agent's configuration and grounding, not in these exports; it is what Modules 2 and 3 go get.
4. Write down the shortest honest answer you can give right now, and underline the parts you had to leave
   as "unknown — needs the tenant or agent config."

</details>

## Summary

You just experienced the gap the rest of the workshop closes. Three plain questions — *how many, who owns
them, what can they access* — have no one-file answer, because an agent's real exposure is spread across
its environment, its connections, its identity, and its grounding. You also met the recurring subtlety in
"who owns them": an owner can be a disabled account, a service principal, a shared mailbox, or someone
different from whoever owns the underlying connection. Keep your rough answers and your list of "unknowns"
— Module 2 (DISCOVER) turns the first two questions into a real inventory, and Module 3 (MAP) turns the
third into effective-access findings.
