# Task 07-01 — Take it home

## Introduction

The questions you answered about Halcourt — how many agents, who owns them, what they can reach — apply to
your own tenant too. Seven questions turn them into a plan: this page maps each one to where you'll find
the answer at home, then gives you a plan for your first week. Fill in the worksheet
when you're back at work, with your own tenant open.

{: .warning }
> This page is about your real organization. Keep any live tenant details — agent names,
> owners, connection strings, data locations — in your own private binder, not in shared
> lab notes. Never paste real secrets or customer data into workshop materials.

## Description

This is a reference page, not a lab. Read the crosswalk to see which tenant surface answers each question.
Then pick your first-week actions using the ranking rule and quick wins below. Last, draft one sentence for
leadership. You'll record all three in the
[Own-Estate Assessment]({% link worksheets/templates/06-own-estate-assessment.md %}) worksheet.

## Success Criteria

- [ ] You know where each of the seven questions is answered in your own tenant.
- [ ] You have the worksheet and know your first quick win.
- [ ] You know the shape of the one sentence you'll take to leadership.

## Key Tasks

### 01: The seven questions in your tenant

Each question uses a technique you practiced today. The table points that technique at the matching
Microsoft surface in your own tenant.

<details markdown="block">
<summary>Expand this section for the crosswalk</summary>

| Question | What you practiced in the lab | Where to look in your tenant |
|---|---|---|
| **Discovery** — how will we inventory our agents? | Joined the five estate exports to list every agent across *all* environments, including the personal ones | The Agent 365 registry (**Microsoft 365 admin center → Agents → All agents → Registry**), then the Power Platform admin center (Agents view), the CoE Starter Kit agent inventory, and Microsoft Graph for agent identities — no single source is complete |
| **Ownership** — who is responsible? | Recorded the *agent* owner, the *connection* owner, and — per operation — the authentication mode and acting credential (Exercise 03) | Agent owner in PPAC / Copilot Studio; connection owner under Connections; for each knowledge source, tool, flow, HTTP or MCP call, whether it uses **End user** or **Maker-provided** credentials and whose credential acts; cross-check every owner against Entra account status |
| **Identity** — which identities need review? | Enumerated the auto-created agent (workload) identities and the accounts connections actually run as | Entra Agent IDs for newer agents, and legacy app-registration service principals tagged `AgentCreatedBy:CopilotStudio` for older ones; each agent's GUID under Copilot Studio → **Settings → Advanced → Metadata → Entra Agent ID**; match active agents against agent identities and investigate any that don't match; plus the service accounts and shared mailboxes behind connections |
| **Access** — which systems/data are highest risk? | Mapped *effective* access: Dataverse records and PII, whole-site SharePoint grounding, HTTP and MCP endpoints | For Dataverse: which principal authorizes the call, its security-role privilege depth, and which records it reaches through ownership, business units, teams, and sharing; the SharePoint scope each agent grounds on; custom connectors, HTTP actions, and MCP servers, and how each authenticates |
| **Controls** — what do we already have? | Tested DLP, environment strategy, Purview labels, Conditional Access, and logging against real failures | Power Platform DLP policies (and which environments they cover); your environment strategy; Purview labels and DLP; Conditional Access, including workload identities — Conditional Access for agents requires Agent 365, and Agent ID Conditional Access is enforced only when the agent runs in Teams |
| **Detection** — would we know if something went wrong? | Tried to link a downstream event back to *who really asked* (Task 05-07) | The `CopilotInteraction` event in Purview Audit; the downstream Dataverse, flow, API, or MCP log and the credential it records; Defender for Cloud Apps; classify attribution as complete, cross-log only, partial, or unavailable |
| **Gaps** — what do we investigate first? | Prioritized findings by effective access and blast radius, not by how risky an agent *sounded* | Your own ranked list — rank by blast radius first; anything severe you can contain right away goes to the top |

> The findings never live in a single file. In the lab they lived in the *joins* — an
> agent whose owner is disabled, a connection owned by someone who left, an environment
> with no DLP. Your tenant is the same: pull the pieces, then look at what only shows up
> when you put them side by side.

### 02: Your first week

Pick three actions, not thirty. A short list you finish beats a long list you admire.

<details markdown="block">
<summary>Expand this section for the ranking rule and quick wins</summary>

**Rank by blast radius first.** Blast radius is how much sensitive data, or how many write and approve
actions, an agent can reach. Anything severe you can contain right away goes to the top — for example,
disabling a connection or unsharing an agent. Effort only breaks ties between actions of similar
importance. Make at least one of your three a quick win.

**Quick wins.** Each of these costs nothing and you can start it yourself this week:

- Pull the five estate exports for your tenant.
- List the agents whose owner account is disabled.
- Find the connections owned by departed users or running as service accounts.
- Check which environments have no DLP applied.
- Match your active agents against the agent identities in Entra and investigate any that don't match.

These are the same joins you ran against Halcourt, now pointed at home. Give each action an owner, a due
date, and a **Done when** in the worksheet. Without those, an action is a wish, not a plan.

</details>

### 03: Make the case

The three actions are for you and your team. Leadership controls your time and budget, so give them one
sentence they'll remember.

<details markdown="block">
<summary>Expand this section for the leadership sentence</summary>

Name the asset in business terms ("customer PII", not "a Dataverse connector"). Name the moment: building
agents has outpaced governing them. Make the ask small: time to inventory and scope, not a platform
purchase.

{: .tip }
> A case that works sounds like this shape: *"Anyone in the company can now build an agent
> that quietly acts with someone else's access to [our most sensitive data], and today we
> can't say how many exist or what they can reach — I need [two weeks / one analyst] to
> inventory and scope them before that becomes an incident."* Make it true for your tenant,
> then make it shorter.

</details>

{: .note }
> Every agent created since May 2026 has an Entra Agent ID. Older agents may still use a
> legacy app registration until Microsoft migrates them. Agent 365 went GA on May 1, 2026.
> The governance surface arrived faster than the governance did.

{: .note }
> Where an answer depends on a fast-moving product detail — which Agent 365 views your
> licensing gives you, which of your agents are already migrated to Entra Agent ID, how
> completely Defender sees Copilot Studio activity — write it down as *"verify in tenant"*
> rather than assuming. Naming the uncertainty is part of the assessment.
