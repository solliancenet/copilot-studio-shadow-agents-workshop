# Task 06-01 — The production promotion gate

## Introduction

The five baseline stages on the
[exercise landing page]({% link docs/06_security_baseline/06_security_baseline.md %}) are useful only if
something *enforces* them. The production promotion gate is that enforcement point: the short,
non-negotiable list of what must be true before an agent is trusted with production data and authority.
This is where KNOW IT → OWN IT → SCOPE IT → CONTROL IT → WATCH IT stops being guidance and becomes a
pass/fail decision, recorded in the
[Gate record]({% link worksheets/templates/05-agent-security-review-checklist.md %}#gate-record) of the
Agent Security Review Checklist.

## Description

Halcourt's gate sorts everything it checks into three categories:

- **Required before production:** the conditions in the gate's table, one per stage from KNOW IT through
  WATCH IT. Each one must be met before promotion.
- **Accepted residual risk:** a control that is implemented and operating but can't fully eliminate the
  risk. The remaining risk is documented and explicitly accepted by the security reviewer, who signs it.
- **Formal temporary exception:** a required control that isn't yet implemented. The exception records
  the reason, compensating controls, accountable approver, remediation owner, remediation date and expiry
  date, and an expired exception blocks continued production use.

In this task you apply the gate rather than design it. You use Halcourt's definition of "production" to
decide which agents must pass, run agents through the required conditions to see where they stall, and
then take Benefits Buddy all the way through: its dented failures, any exception it needs, and the
security reviewer's sign-off. Everything goes in the Gate record, working from the artifacts you built in
the tenant or from the artifact pack.

```mermaid
flowchart TD
  A["Agent in production by Halcourt's definition"] --> K{"KNOW IT complete?<br/>inventory · purpose · sensitivity"}
  K -->|no| X["Do not promote — remediate"]
  K -->|yes| O{"OWN IT complete?<br/>3 roles · live owner · connection owner verified"}
  O -->|no| X
  O -->|yes| S{"SCOPE IT complete?<br/>least privilege · no secrets in config"}
  S -->|no| X
  S -->|yes| C{"CONTROL IT + WATCH IT<br/>controls operating?"}
  C -->|yes| R{"Residual risk<br/>documented + accepted?"}
  C -->|no| E{"Formal exception<br/>valid and unexpired?"}
  E -->|no| X
  E -->|yes| R
  R -->|no| X
  R -->|yes| G["Security reviewer signs + dates"]
  G --> P["Promote to production"]
```

## Key Tasks

### 01: Apply Halcourt's definition of production

The most expensive lifecycle failure in this estate is an agent that did production work under a "test"
label and never faced a promotion review. If your gate keys off the environment's name, that agent walks
straight past it. So Halcourt defines production by exposure:

> **Halcourt's definition of production.** An agent is in production, and must pass the gate, if *any* of
> these is true, whatever environment it lives in:
>
> - **Others use it.** Anyone other than its maker can chat with it.
> - **It reaches sensitive data.** Its **Data sensitivity** in your
>   [Exercise 02 inventory]({% link worksheets/templates/01-agent-estate-inventory.md %}) is PII or
>   Compensation.
> - **It acts.** It writes, approves or sends anything, or changes anything beyond the maker's own files.

{: .note }
> Your own organization's definition may vary in the details — for example, some count any customer data,
> some count internal-only use — but it should be keyed to exposure, not the environment's name or type.

### 03: Handle dented failures, exceptions and sign-off

An agent with a **DENTS IT** failure passes the gate only with a layered control or a documented, signed
residual risk.

<details markdown="block">
<summary>Expand this section for detailed steps</summary>

1. In your [Exercise 05 matrix]({% link worksheets/templates/04-control-efficacy-matrix.md %}), list
   every **DENTS IT** cell on Benefits Buddy's failures: Scenario A (grounding injection) and Scenario B
   (exfiltration). For each one, choose:
   - **Layer it.** Name a second control that, together with the first, raises the bar — for example,
     scoped grounding plus an encrypting label. Confirm both are operating.
   - **Accept it.** Record the remaining risk and why the controls can't remove it. The security
     reviewer signs and dates it.

   Record each choice as a row in the **DENTS IT failures** table of the
   [Gate record]({% link worksheets/templates/05-agent-security-review-checklist.md %}#gate-record).
2. A **formal temporary exception** records:
   - the reason;
   - the compensating controls;
   - the accountable approver;
   - the remediation owner;
   - the remediation date;
   - the expiry date — an expired exception blocks continued production use.

   If an agent needs one, record it in the **Formal temporary exception** table of the Gate record.
3. Walk **Benefits Buddy** through the gate completely, stage by stage: record its **Production?** call
   and where it stalls or passes in the first table of the Gate record, then record the **security
   reviewer sign-off** — name and date — at the bottom.
4. Compare your record with the suggested one below.

</details>

{: .note }
> Promotion without a signature is not a gate.

{: .important }
> The gate is deliberately unromantic. It does not promise an agent is safe — it promises that a named
> person looked at each trust boundary, closed what could be closed, documented and signed the risk that
> remains, and put a deadline on any exception. That is the difference between an estate you govern
> and one you merely host.

ended with the security reviewer's sign-off in the Gate record of your Agent Security Review Checklist.
