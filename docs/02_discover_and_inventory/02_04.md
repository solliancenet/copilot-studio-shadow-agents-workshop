# Task 02-04 — Produce the Agent Estate Inventory

## Introduction

This is the checkpoint for Module 2. Everything you have gathered — the complete rows from Task 02-02 and
the confirmed hunts from Task 02-03 — now becomes the finished **Agent Estate Inventory**: every agent, every
column, each flag set with evidence, and a set of counts you can defend to leadership. This document is the
foundation the rest of the day builds on; a hole here becomes a blind spot in every later module.

## Description

You will consolidate your working notes into the [01 — Agent Estate Inventory]({% link worksheets/templates/01-agent-estate-inventory.md %})
template: finalize the inventory table, set each flag per agent in the flags matrix, and compute the counts.
Then you sanity-check the whole thing against the estate before you call it done.

## Success Criteria

- [ ] The inventory table is complete — one row per agent, every column filled, all four environments represented.
- [ ] The flags matrix has a decision for **every** agent on every flag: orphaned, shadow, test→prod, shared connection, unknown/ambiguous owner, nobody realizes it exists.
- [ ] Every agent you marked "clean" carries a one-line justification (from Task 02-03).
- [ ] The counts are filled: agents found, environments covered, agents with a disabled or ambiguous owner, agents on a shared/service-account connection.
- [ ] Environments covered equals **four** — you can name them, and you did not silently drop the sandbox or default environment.
- [ ] The finished inventory is saved to your Estate Binder.

## Key Tasks

### 01: Set each flag per agent

Transfer the confirmed results of your five hunts into the flags matrix. The rule: every agent gets a
decision on every flag — including "no." A blank cell is an un-reviewed agent, not a clean one.

<details markdown="block">
<summary>Expand this section for detailed steps</summary>

1. Open the **Flags — the problem estate** matrix in the template. The columns are: Orphaned?, Shadow?,
   Test→Prod?, Shared connection?, Unknown / ambiguous owner?, Nobody realizes it exists?
2. For each agent, mark each flag **yes** or **no** based on the confirmed hunt from Task 02-03 — the join
   plus the second data point, not a single column.
3. Remember an agent can hit **several** flags at once (an orphaned agent on a surviving connection is both
   orphaned and a shared-connection finding). Mark all that apply.
4. For every agent that comes out all-"no", confirm you have the written justification from Task 02-03. A
   clean agent with no reason is not cleared.
5. Note the "Nobody realizes it exists" flag is a judgment built from the others — an agent in a personal
   environment, or one whose owner is gone, is a strong candidate for being off everyone's radar.

</details>

### 02: Compute the counts and finalize

The counts turn the inventory into a headline leadership can act on. Fill them, then sanity-check the whole
deliverable before you close it out.

<details markdown="block">
<summary>Expand this section for detailed steps</summary>

1. Fill the **Count** section of the template: agents found; environments covered; agents with a disabled
   or ambiguous owner; agents on a shared/service-account connection.
2. **Sanity-check environments covered = 4.** Name them — `Meridian (default)`, `Meridian-Prod`,
   `Claims-Test`, `Maker-Sandbox`. If your inventory only has agents from the environments you were told
   about, you missed the point of the exercise; go back to the artifact pack.
3. **Sanity-check the owner counts against the users export.** Your "disabled or ambiguous owner" count
   should be reconcilable against `users-export.csv` (`account_enabled = FALSE`, `is_service_account`,
   `is_shared_mailbox`). If the numbers do not line up, one of your joins is wrong.
4. **Confirm no agent is unjustified.** Every row is either flagged with evidence or cleared with a reason.
5. **Save the finished inventory to your Estate Binder.** It is the input to Module 3, where you turn "what
   exists" into "what can it actually reach, and as whom."

</details>

{: .important }
> **Module checkpoint.** You have passed Module 2 when your inventory has one row per agent across all four
> environments, every flag is decided with evidence, every clean agent is justified, and your counts
> reconcile against the exports. Do not move on with blanks — an unmapped agent is an ungoverned one.

{: .tip }
> Keep the inventory in a form you can re-sort. In Module 3 you will pivot the same data by identity and by
> connection, and in Module 7 you will reuse this exact method against your **own** estate.

## Summary

You produced the Agent Estate Inventory: a complete, one-row-per-agent record across every environment, a
flags matrix with an evidence-backed decision for each agent, justifications for the ones you cleared, and
counts that reconcile against the source exports. That is the answer to "what do we actually have?" — and
the foundation for [Exercise 03]({% link docs/03_identity_and_effective_access/03_identity_and_effective_access.md %}),
where you map each agent's effective access and the identity it truly acts as.
