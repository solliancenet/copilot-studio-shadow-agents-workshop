# Task 02-01 — Where agents hide: discovery surfaces

## Introduction

You cannot secure what you cannot see. Before you build the inventory, you need to know **where** agents
show up, and — more importantly — where they **don't**. Every discovery surface has a viewport and a
blind spot. If you inventory from one surface only, you will confidently miss the agents that matter most:
the ones in personal and "test" environments that nobody registered, and the ones whose real authority
lives in a connection the surface never shows you.

## Description

You will walk the discovery surfaces available for a Copilot Studio estate, and for each one record two
things: **what it reveals** and **what it misses**. You then name the blind spots explicitly and decide
which surface you will actually build the Halcourt Mutual inventory from. For this lab the reliable,
always-available surface is the exported **artifact pack**; the live tenant surfaces are there to
corroborate and to show you how this looks in production.

## Success Criteria

- [ ] You can list the discovery surfaces available for a Copilot Studio estate and state, for each, what it reveals.
- [ ] For each surface you have recorded at least one thing it **misses**.
- [ ] You have named the personal / sandbox environment blind spot in your own words.
- [ ] You can state the difference between an **agent owner** and a **connection owner**, and why a surface that shows only one hides authority.
- [ ] You have chosen the surface(s) you will build the inventory from, and confirmed the offline path from the artifact pack works.

## Key Tasks

### 01: Map the discovery surfaces

Work through each surface below. For each, open it (or read its description) and write down, in your notes,
what it shows you and what it leaves out.

![Power Platform admin center Agents view listing agents across environments](../../media/ex02_t01_kt01_s01.png)

<details markdown="block">
<summary>Expand this section for detailed steps</summary>

1. **Power Platform admin center (PPAC) — Agents / Copilots view.** In the admin center, browse
   environments and their agents. This reveals agents that exist inside environments the admin center
   enumerates, with owner, environment, and state. What it misses: it only shows environments you can see
   and are looking at — it is easy to review `Halcourt-Prod` and never open `Maker-Sandbox` or the
   `Halcourt (default)` environment where anyone can build.
2. **CoE Starter Kit inventory.** The Center of Excellence Starter Kit syncs an inventory of makers,
   apps, flows, and agents into Dataverse and surfaces it in dashboards. This is the closest thing to a
   single pane. What it misses: it only inventories what its sync **reaches** and is **configured** for —
   environments excluded from the sync, or added after the last run, are simply absent, and it reports the
   *agent* owner, not the identity a connection runs as.
3. **Microsoft Graph — agent and workload identities.** Since agents began getting auto-created Entra
   identities, you can enumerate them through Graph as service principals, each named
   `<agent name> (Microsoft Copilot Studio)`, with no app registration behind them. This reveals the
   workload identities themselves — useful when an agent exists but its owner is gone. What it misses: an
   identity in Graph does not tell you which environment the agent lives in, what it grounds on, or what
   connections it uses; you have to correlate it back to the estate. And it over-counts: deleting an agent
   — even deleting its whole environment — does not remove the agent's identity. Each rebuild of this
   lab's estate left the previous build's identities behind, so Graph can list identities for agents that
   no longer exist.
4. **Agent 365 admin experience (where available).** The Agent 365 governance surface is intended to give
   admins a catalog of agents with ownership, usage, and risk signals. Treat its exact views as an evolving
   2026 surface — confirm what your tenant actually exposes rather than assuming a specific screen exists.
5. **The exported artifact pack.** Five CSVs — [`agents-export.csv`]({% link worksheets/artifact-pack/agents-export.csv %}),
   [`connections-export.csv`]({% link worksheets/artifact-pack/connections-export.csv %}),
   [`agent-identities-export.csv`]({% link worksheets/artifact-pack/agent-identities-export.csv %}),
   [`users-export.csv`]({% link worksheets/artifact-pack/users-export.csv %}), and
   [`environments-export.csv`]({% link worksheets/artifact-pack/environments-export.csv %}). This is a
   point-in-time snapshot across all four environments. It reveals the joins no single live surface shows
   you in one place. What it misses: it is a snapshot — it can go stale, and it only contains what was
   exported.

</details>

### 02: Name the blind spots

A surface tour is only useful if you can say where each one goes dark. Record these blind spots against
the Halcourt Mutual estate specifically.

<details markdown="block">
<summary>Expand this section for detailed steps</summary>

1. **Personal and sandbox environments are the primary blind spot.** In `environments-export.csv`, note
   that `Maker-Sandbox` is a **Developer** (individual-maker) environment and `Halcourt (default)` allows
   **all users** to build. Agents born in these are exactly the ones a "review the production environments"
   pass will never see. Write down: which environments would a casual review skip, and why?

   Access is part of this blind spot. Anything that reads agent records environment by environment — a
   script, `pac`, a Dataverse query — sees only the environments where your account holds a security role.
   A Developer environment's only System Administrator is the maker who owns it, and in this lab's tenant
   the admin — holding only Environment Maker and Basic User in the default environment — read zero agents
   there. An empty result can mean *no access*, not *no agents*.
2. **Agent owner is not connection owner.** Open `connections-export.csv` next to `agents-export.csv`. The
   agent has an `owner_upn`; each connection has its own `connection_owner_upn`. These are frequently
   **different people**. A surface that lists only the agent owner tells you who built the bot, not whose
   authority it exercises when it acts. Note this distinction now — Task 02-03 turns it into a hunt.
3. **Some agents are in nobody's mental inventory.** An agent can be published and active while the person
   who would review it is gone, or while it sits in an environment no one governs. No surface flags "nobody
   realizes this exists" for you — it falls out of the joins you are about to build.
4. **Some credentials are not connections.** Three rows in `connections-export.csv` — the HTTP action,
   the MCP server and the Power Automate flow — are not Power Platform connections. The pack lists them so
   every credential sits in one file. In the tenant, the API key and the bearer token live inside the
   agent's own configuration, and no connections list shows them: an inventory built from connections
   alone misses exactly the static secrets.
5. **Decide your source of truth.** For this lab, build the inventory from the artifact pack and use any
   available live surface (PPAC, CoE, Agent 365) to corroborate. The pack guarantees you can complete the
   work offline.

</details>

{: .important }
> The exact 2026 admin surfaces — the precise Agent 365 governance views, how the CoE Starter Kit reports
> newly auto-created agent identities, and how Graph exposes agent workload identities — are still
> evolving. Treat any specific screen described here as something to **verify in your own tenant**, and
> fall back to the artifact pack as the surface that always works.

{: .note }
> The point of a surface inventory is not to pick the "best" tool. It is to understand that each tool has a
> blind spot, so you can deliberately cover the gaps. The joins in the artifact pack exist precisely because
> no single live view puts owner, connection owner, identity, and environment in one place.

## Summary

You mapped the discovery surfaces for a Copilot Studio estate — PPAC, the CoE Starter Kit, Microsoft Graph
for workload identities, the Agent 365 admin experience, and the exported artifact pack — and recorded what
each one reveals and misses. You named the two blind spots that will bite hardest at Halcourt Mutual:
personal and sandbox environments, and the gap between the agent owner and the connection owner. With the
artifact pack chosen as your always-available source of truth, you are ready to join the exports into a
single inventory.
