# Task 05-06 — Purview

## Introduction

Purview is a **data-classification** control. Sensitivity labels, auto-labeling, sensitive-information
types (like SSN), and data loss prevention act on the *data object itself* — the file, the record — rather
than on the connector or the identity. Keep three things apart: a label that **classifies** (and is
displayed), a label that **encrypts** — which withholds content from Copilot unless the requester holds
VIEW and EXTRACT rights — and Purview **DLP policies** keyed on labels. Copilot Studio can't ground on a
file protected by an encrypting label at all — it can't read it, even for users who can open it — while a
label that only classifies doesn't stop grounding. So what this control does to Scenario B depends on what
the label enforces. This task tests how far that holds, and names the two places classification does not
reach.

## Description

You will inspect the `Confidential-PII` label on a pre-labeled copy of the leadership compensation file
(`Leadership/2026-comp-bands-labeled.xlsx`), compare what Benefits Buddy can ground on in the labeled and
unlabeled copies, and confirm the SSN sensitive-information type covers Customer PII. Then you retest
**Scenario B** (Benefits Buddy surfacing the comp file) and **Scenarios C/D** (Customer PII through Claims
Copilot's Dataverse connection), and record where labeling withholds the data versus where connector-level
access makes the label moot. You also note the one thing a label on a *file* can never stop: an
*instruction* hidden in grounding content, which is text, not classified data.

## Success Criteria

- [ ] You inspected `Confidential-PII` on the labeled copy and recorded what it enforces (encryption, and
  who holds VIEW and EXTRACT), and confirmed the SSN sensitive-information type for Customer data.
- [ ] You compared what Benefits Buddy can ground on in the labeled and unlabeled copies.
- [ ] You re-ran Scenario B and Scenarios C/D and observed whether the labeled data was withheld.
- [ ] You recorded **CLOSES IT / DENTS IT / MISSES IT** verdicts for Purview against B and C/D in the
  [Control Efficacy Matrix]({% link worksheets/templates/04-control-efficacy-matrix.md %}), each with a
  remaining-risk note.
- [ ] You can name where classification helps (the content layer) and where it does not (the
  connector-authorization layer, and injected instructions).

<summary>Reveal the suggested verdicts and reasoning</summary>

- **Purview × B:** suggested **CLOSES IT** for the labeled copy: Copilot Studio can't ground on a file with
  an encrypting label, so the comp figures aren't reachable. The unlabeled original stays exposed — the
  remaining risk is every sensitive file that isn't labeled yet.
- **Purview × C/D:** suggested **MISSES IT** or a weak **DENTS IT**. Classifying SSNs can raise the bar on
  some export paths, but it does not block a Dataverse read `svc-claims` is already authorized to make —
  that lever was least privilege (Task 05-03).
- **Scenario A:** an instruction is not data, so classification does not reach it.

</details>

## Summary

Purview is the content-layer control. An encrypting label puts a file out of the agent's reach, so what it
does to Scenario B depends on what the label enforces. Against the PII in Scenarios C and D, a classification
doesn't re-authorize a connector read, and an injected instruction isn't data at all. Record the verdict and
remaining risk in the matrix.
